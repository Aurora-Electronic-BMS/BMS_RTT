核心概念乒乓缓存环形缓冲区

当上位机开始发送固件数据包时，Bootloader必须像一个高效的仓库管理员，不仅要准确接收每一件“货物”（数据），还要有临时存放的“货架”（缓存），并确保货物不会堆积或丢失。固件接收与缓存管理，就是设计这套接收和暂存系统的核心。

生活类比：快递驿站

你可以把Bootloader接收固件想象成快递驿站接收包裹。串口一次只能送一个小包裹（一帧数据），而整个固件有成百上千个包裹。驿站需要一个临时货架（缓存）来堆放这些包裹，等凑够一定数量或收齐了，再一次性搬运到最终仓库（Flash）。如果货架满了或者包裹顺序乱了，整个升级就会失败。

技术定义：固件接收与缓存管理指在Bootloader中，通过特定的内存区域（缓存区）暂存从通信接口（如串口）接收到的固件数据片段，并采用一种组织策略（如环形缓冲区、乒乓缓存）来协调数据写入与后续处理（如校验、写入Flash）速度不匹配的问题，确保数据流的完整性与顺序性。

7.1 数据接收的两种模式

接收固件数据不是简单地把字节存起来。你需要决定何时、以多大的块来处理数据。实际项目中，主要有两种模式。

上位机发送
→
接收中断
→
缓存区
↓
模式一：字节接收
→
逐字节处理
↓
模式二：块接收
→
集齐一包再处理

模式一：中断驱动，逐字节接收。这是最基础的方式。串口每收到一个字节，就触发一次接收中断，在中断服务函数里将这个字节存入缓存区。这种方式实时性高，但频繁中断在高速率或大数据量时会对系统造成负担。

// 示例：串口接收中断服务函数（HAL库）
void USART1_IRQHandler(void) {
  uint8_t received_byte;
  if(__HAL_UART_GET_FLAG(&huart1, UART_FLAG_RXNE)) {
    received_byte = (uint8_t)(huart1.Instance->DR & 0xFF); // 读取数据
    RingBuffer_WriteByte(&rx_buffer, received_byte); // 写入环形缓冲区
  }
}

模式二：DMA驱动，块接收。这是更高效、更推荐的方式。配置DMA（直接存储器访问）控制器，让它在串口收到数据后，自动将一整块数据（比如256字节）搬运到指定的内存缓存区，搬运完成才产生一次中断通知CPU。这极大解放了CPU，特别适合固件升级这种连续大数据量传输。

模式选择建议：对于STM32F1/F4等系列，如果升级波特率在115200以上，强烈建议使用DMA模式。我在一个使用F407的项目中，将接收模式从中断改为DMA，CPU占用率从频繁波动的30%以上降至几乎忽略不计，且数据传输的稳定性显著提升。

7.2 缓存区的设计与选择

无论采用哪种接收模式，你都需要一块内存作为缓存区。这块内存怎么组织，决定了数据管理的效率和复杂度。

缓存策略工作原理优点缺点适用场景
单一大缓存分配一块大内存（如2KB），数据顺序存入，写满或收齐一包后整体处理。实现简单，逻辑直观。处理数据时无法接收新数据，易造成数据丢失；内存利用率可能不灵活。数据包很小且间隔长的简单应用。
环形缓冲区将线性内存首尾相连成环，用读/写指针管理。写入和读出可以同时异步进行。高效利用内存，支持生产/消费异步模型，避免数据覆盖。实现稍复杂，需要维护指针；缓冲区大小固定。中断字节接收模式的标配，处理流式数据的经典选择。
乒乓缓存准备两块同样大小的缓存区（A和B）。当A区收满数据后，切换去收B区，同时处理A区数据。读写完全分离，无竞争；适合块处理。需要双倍内存；逻辑状态管理需谨慎。DMA块接收模式的理想搭档，固件升级的常用方案。

对于固件升级，“DMA + 乒乓缓存”是黄金组合。DMA负责高效搬运数据块到当前活跃的缓存区，当一块填满，触发DMA传输完成中断，在中断中切换DMA目标地址到另一块缓存区，同时通知主循环处理刚刚填满的那块数据（如计算CRC、写入Flash）。

乒乓缓存工作流程

  1. 初始化：分配两块缓存区（如buffer_A[1024]， buffer_B[1024]），设置DMA指向buffer_A。
  2. 阶段1：DMA向buffer_A搬运数据，主程序空闲或处理其他任务。
  3. 阶段2：buffer_A满，DMA传输完成中断触发。在中断中，立即将DMA目标地址改为buffer_B，并设置一个标志（如`buffer_a_ready = 1`）。
  4. 阶段3：DMA开始向buffer_B搬运数据，同时主循环检测到`buffer_a_ready`标志，开始处理buffer_A中的数据（校验、写入Flash）。
  5. 循环：如此往复“乒乓”切换，实现接收与处理的并行。

编者提示：小心DMA中断的“重入”与指针切换时机。在DMA传输完成中断中切换缓存区指针时，务必确保在切换DMA目标地址之前，已经保存好了当前已满缓存区的信息（如它的起始地址和长度）。一个常见的坑是：先切换了活跃缓冲区指针，然后才去设置“数据就绪”标志，如果此时另一个中断或高优先级任务修改了指针，就会导致标志指向错误的缓存区。我的经验是，在中断里用一个局部变量保存“已满缓冲区”的地址，再更新DMA和全局指针。

7.3 实战：构建一个乒乓缓存管理器

下面我们用一个简化的结构体和函数组，来实现一个用于固件升级的乒乓缓存管理器。假设我们通过串口DMA接收，每包固件数据长度为512字节。

// 乒乓缓存管理器结构体
typedef struct {
    uint8_t* buffer[2];      // 两个缓存区指针
    volatile uint8_t active_idx; // 当前DMA正在写入的缓存区索引 (0或1)
    volatile uint8_t ready_flag; // 位标志：bit0表示buffer0就绪，bit1表示buffer1就绪
    uint32_t packet_size;     // 每个数据包的大小（字节）
} PingPongBuffer_t;

// 初始化函数
void PingPongBuffer_Init(PingPongBuffer_t* ppb, uint8_t* buf0, uint8_t* buf1, uint32_t pkt_size) {
    ppb->buffer[0] = buf0;
    ppb->buffer[1] = buf1;
    ppb->active_idx = 0;
    ppb->ready_flag = 0;
    ppb->packet_size = pkt_size;
    // 配置DMA，初始目标地址指向buffer[0]
    HAL_UART_Receive_DMA(&huart1, ppb->buffer[0], pkt_size);
}

// DMA传输完成中断回调函数（在stm32xx_it.c中调用）
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart->Instance == USART1) {
        uint8_t finished_idx = g_ppb.active_idx; // 保存刚填满的缓冲区索引
        
        // 1. 设置“数据就绪”标志
        g_ppb.ready_flag |= (1 << finished_idx);
        
        // 2. 切换活跃缓冲区索引
        g_ppb.active_idx ^= 1; // 与1异或，在0和1之间切换
        
        // 3. 重新启动DMA接收，指向新的活跃缓冲区
        HAL_UART_Receive_DMA(&huart1, 
                              g_ppb.buffer[g_ppb.active_idx], 
                              g_ppb.packet_size);
    }
}

// 主循环处理函数
void ProcessReadyBuffer(void) {
    if (g_ppb.ready_flag & 0x01) { // buffer0 就绪
        HandleFirmwareData(g_ppb.buffer[0], g_ppb.packet_size);
        g_ppb.ready_flag &amp;= ~0x01; // 清除就绪标志
    }
    if (g_ppb.ready_flag & 0x02) { // buffer1 就绪
        HandleFirmwareData(g_ppb.buffer[1], g_ppb.packet_size);
        g_ppb.ready_flag &amp;= ~0x02;
    }
}

常见误区

  • 缓存区大小设置不当：缓存区大小必须等于或大于DMA每次传输的数据块大小。如果DMA配置为接收256字节，缓存区却只有200字节，会导致内存越界，系统崩溃。
  • 未使用`volatile`关键字：在中断和主循环共享的标志变量（如`active_idx`, `ready_flag`）前必须加`volatile`，防止编译器优化导致读写不同步。
  • 在中断中执行耗时操作：DMA传输完成中断应只做标志设置和指针切换等轻量操作，绝对不能在中断里进行CRC计算或Flash写入等耗时任务，这会导致中断阻塞，丢失后续数据。

7.4 处理数据流中断与超时

实际网络或串口传输中，数据流可能不是连续的。上位机发送完一个包后可能需要准备下一个包，或者线路出现短暂干扰。Bootloader必须能判断“一个数据包是否完整接收”以及“传输是否已异常中断”。

包完整性判断

  • 依赖固定包长：如果协议规定每包固定N字节，则收满N字节即认为包完整。这是最简单的方式。
  • 依赖协议帧头尾：通过识别帧头、帧尾和长度字段来判断包边界。这更灵活，但解析稍复杂。

传输超时判断

  • 字节间超时：使用一个硬件定时器，每收到一个字节就重置定时器。如果超过设定时间（如50ms）未收到新字节，则认为当前包传输结束或链路中断。
  • 包间超时：在等待新数据包开始时计时。如果超过更长时间（如5秒）未收到任何数据，则认为整个升级会话超时，应复位或返回错误。

实现超时机制通常结合STM32的基本定时器（如TIM6/7）。在接收开始时或收到字节时重置定时器计数，在定时器中断中检查超时状态。我在项目中通常将字节间超时设置为波特率下传输10个字节所需时间的3-5倍，这是一个比较保险的经验值。

动手试一试

在STM32CubeIDE中，基于一个STM32F103C8T6工程（假设已配置好USART1和DMA），尝试实现以下功能：

  1. 定义两个1024字节的数组作为乒乓缓存区，并初始化一个`PingPongBuffer_t`结构体。
  2. 将USART1的DMA接收配置为循环模式（Circular），目标地址指向第一个缓存区，长度为1024。
  3. 在DMA传输完成中断回调函数中，不切换缓存区，而是仅打印“Buffer Full”信息并清除中断标志。
  4. 在主循环中持续检查一个全局计数变量，观察DMA中断触发的频率。

这个实验能帮助你直观感受DMA块接收的工作方式，理解“传输完成中断”的含义。注意，循环模式下DMA会在收满指定长度后自动从头开始覆盖，所以这里我们只是观察，不进行真正的乒乓切换。

本章小结

  • 固件接收主要有中断逐字节和DMA块传输两种模式，后者效率更高，更适合固件升级。
  • 缓存管理策略中，环形缓冲区适合流式字节接收，而乒乓缓存与DMA块接收是黄金组合，能实现接收与处理的完全并行。
  • 实现乒乓缓存需精心管理双缓冲区指针和“数据就绪”标志，共享变量必须使用volatile修饰，且中断服务函数应保持简短。
  • 必须设计超时判断机制（如字节间超时、包间超时）来处理数据流不连续或传输中断的异常情况，确保升级流程的健壮性。
