核心概念DFU模式DFU描述符

当你的设备外壳封闭，或者需要比串口快得多的升级速度时，USB DFU（Device Firmware Upgrade）就成了理想选择。它允许设备通过USB接口被识别为一个特殊的“固件升级设备”，由上位机工具直接操控内部Flash的擦写。我在一个手持医疗设备项目中就采用了这种方式，用户只需用USB线连接电脑，运行升级程序即可完成更新，完全无需打开设备外壳，体验非常好。

DFU模式：设备的“恢复模式”

你可以把DFU模式理解为智能手机的“恢复模式”或“刷机模式”。设备进入这个特殊状态后，不再运行正常的应用程序，而是运行一个专用于接收新固件并写入Flash的小程序。对于STM32，这个小程序可以是芯片出厂时固化在系统存储区（System Memory）的内置DFU Bootloader，也可以是你自己实现的自定义DFU Bootloader。

STM32内置DFU Bootloader

大多数STM32系列（如F0/F1/F2/F3/F4/F7/L0/L1/L4）都在芯片内部预留了一块只读的系统存储区，里面固化了一个由ST官方提供的Bootloader。这个Bootloader支持多种接口，USB DFU是其中最常用的一种。使用它的最大好处是你无需自己编写任何Bootloader代码，只需要让芯片进入这个模式，然后使用ST提供的工具即可升级。

要使用内置Bootloader，首先必须让芯片从系统存储区启动。具体方法是通过配置启动模式引脚（BOOT0, BOOT1）或修改用户选项字节（User Option Bytes）中的`nBOOT1`和`nBOOT0`位。不同系列芯片的启动模式配置略有差异，下表以常见的STM32F1和STM32F4系列为例：

芯片系列BOOT0引脚BOOT1引脚/选项位启动模式用途
STM32F10x从主Flash启动运行用户App
10从系统存储器启动进入内置Bootloader
11从内置SRAM启动调试用
STM32F40x从主Flash启动运行用户App
10从系统存储器启动进入内置Bootloader
11从内置SRAM启动调试用

实际项目中，我们通常不会让用户去拨动硬件跳线。更常见的做法是：在用户应用程序中，检测到一个特定的触发条件（如长按某个按键），然后软件修改选项字节，并执行系统复位，让芯片自动进入DFU模式。STM32CubeHAL库提供了操作选项字节的API。

// 示例：在用户App中，通过软件方式配置从系统存储器启动（STM32F4系列）
void Enter_DFU_Bootloader_Software(void) {
    // 1. 解锁选项字节寄存器
    HAL_FLASH_OB_Unlock();

    // 2. 设置选项字节结构体，将nBOOT_SEL置1，nBOOT0置0（具体位定义需查参考手册）
    FLASH_OBProgramInitTypeDef OBInit;
    OBInit.OptionType = OPTIONBYTE_USER;
    OBInit.USERConfig = OB_BOOT_SEL_SYSTEM | OB_BOOT0_RESET; // 假设的宏，实际名称需根据芯片型号确定
    HAL_FLASHEx_OBProgram(&OBInit);

    // 3. 加载新的选项字节并执行系统复位
    HAL_FLASH_OB_Launch(); // 此函数内部会触发复位
    // 复位后，芯片将从系统存储器启动，进入DFU模式
}

⚠️ 常见误区

  • 混淆BOOT引脚与选项字节：硬件BOOT引脚的电平在复位瞬间被锁存，决定启动模式。而选项字节是存储在Flash中的配置，复位时被读取。如果同时配置，选项字节的优先级通常更高（具体需查芯片手册）。
  • 未解锁Flash就修改选项字节：修改选项字节前，必须依次调用HAL_FLASH_Unlock()和HAL_FLASH_OB_Unlock()，否则操作会失败。
  • USB连接不稳定：内置DFU Bootloader通常使用USB FS（全速）模式。确保USB数据线质量可靠，且PC端USB端口供电充足。连接不稳定会导致枚举失败或传输中断。

USB DFU协议与描述符

当芯片以DFU模式启动并通过USB连接到主机后，它需要告诉主机：“我是一个DFU设备”。这是通过USB协议中的描述符（Descriptor）来实现的。DFU设备除了标准的设备描述符、配置描述符、接口描述符外，还必须包含一个特殊的DFU功能描述符（DFU Functional Descriptor）。

这个DFU功能描述符定义了设备的固件升级能力，比如它支持哪些命令、擦写Flash时以多少字节为一个传输块（wTransferSize）、升级完成后是否需要手动断开连接（bmAttributes字段的bitWillDetach标志）等。上位机工具（如STM32CubeProgrammer）就是通过读取这个描述符来知道如何与你的设备正确通信的。

如果你使用内置Bootloader，这些描述符已经预先定义好了。如果你要自己实现一个自定义的USB DFU Bootloader，那么你需要在工程中正确配置这些描述符。在STM32CubeMX中，你可以通过Middleware->USB_Device->DFU来轻松配置相关参数。

编者提示： 实际开发中，如果你发现电脑无法识别出DFU设备，或者STM32CubeProgrammer连接不上，第一步就应该检查USB枚举是否成功。可以借助工具如“USBlyzer”或“Wireshark（配合USBPcap）”抓取USB数据包，查看设备描述符和DFU功能描述符是否正确返回。我遇到过因为DFU描述符中wTransferSize设置得与Flash编程接口不匹配，导致上位机一直发送错误长度数据包的问题。

使用STM32CubeProgrammer进行升级

STM32CubeProgrammer（STM32CubeProg）是ST官方的多合一编程工具，支持USB DFU、串口、JTAG/SWD等多种连接方式。通过USB DFU升级的流程非常直观。

操作中有几个关键点需要注意：

  1. 连接：在“Connectivity”选项卡中选择“USB”。如果设备枚举成功，下方日志会显示“Device connected”以及读到的DFU描述符信息。
  2. 地址：在“Download”选项卡中，起始地址（Start Address）必须设置为0x08000000（主Flash起始地址）。如果你之前把Bootloader放在了0x08000000，而App放在0x08008000，那么这里就应该填App的起始地址。内置DFU Bootloader会从这个地址开始写入数据。
  3. 选项字节：你可以在“OB”选项卡中查看和修改选项字节。例如，升级完成后，通常需要把启动模式改回从主Flash启动，并勾选“Apply after connection”和“Apply during download”以确保设置生效。

场景：使用内置Bootloader

  • 优点：无需开发Bootloader，稳定可靠。
  • 流程：配置BOOT引脚/选项字节 → USB连接 → CubeProgrammer下载。
  • 注意：需确保产品留有进入DFU模式的物理或软件入口。

场景：开发自定义DFU Bootloader

  • 优点：可集成自定义协议、加密、UI提示等。
  • 流程：用STM32CubeMX生成DFU设备框架 → 实现Flash编程逻辑 → 与App协同。
  • 注意：需正确处理描述符和DFU类请求。

自定义DFU Bootloader开发要点

当内置Bootloader无法满足你的需求时（比如你需要升级过程有LED指示，或者需要先解密再烧写），就需要开发自己的DFU Bootloader。基于STM32CubeMX和HAL库，这个过程可以简化。

首先，在CubeMX中创建一个新工程，选择你的芯片。在“Middleware”中启用“USB_Device”，并在“Class For FS IP”中选择“DFU”。这会自动生成USB设备栈和DFU类框架代码。你需要重点关注并实现以下几个回调函数：

  • uint8_t DFU_Init_FS(void)：DFU模式初始化，在这里初始化你的Flash接口、GPIO等。
  • uint8_t DFU_DeInit_FS(void)：DFU模式退出处理。
  • uint8_t DFU_Erase_FS(uint32_t Add)：擦除指定地址的Flash扇区。
  • uint8_t DFU_Write_FS(uint8_t *src, uint8_t *dest, uint32_t len)：将数据写入目标Flash地址。这是最核心的函数，你需要在这里调用HAL_FLASH_Program()。
  • uint8_t DFU_Read_FS(uint8_t *src, uint8_t *dest, uint32_t len)：从Flash读取数据，用于校验。

你的自定义Bootloader同样需要处理应用程序跳转。在完成固件下载和校验后，需要执行系统复位，或者直接通过函数指针跳转到用户应用程序的入口（通常是0x08000000 + 偏移量）。

// 示例：在自定义DFU Bootloader中跳转到应用程序
void JumpToApplication(uint32_t AppAddress) {
    typedef void (*pFunction)(void);
    pFunction Jump_To_App;

    uint32_t JumpAddress = *(__IO uint32_t*)(AppAddress + 4); // 复位向量地址
    Jump_To_App = (pFunction) JumpAddress;

    // 设置主堆栈指针
    __set_MSP(*(__IO uint32_t*)AppAddress);

    // 关闭所有中断
    __disable_irq();

    // 跳转
    Jump_To_App();
}

动手试一试

找一块支持USB的STM32开发板（如STM32F407 Discovery，它板载了USB FS接口）。

  1. 将BOOT0跳线帽接到高电平（3.3V），BOOT1接到低电平（GND）。
  2. 通过Micro-USB线将开发板的USB口（注意是连接MCU的那个，不是ST-LINK虚拟串口那个）连接到电脑。
  3. 打开设备管理器，你应该能看到一个“STM32 BOOTLOADER”设备出现在“通用串行总线设备”或“通用串行总线控制器”下。
  4. 打开STM32CubeProgrammer，选择USB连接方式，点击“Connect”。如果成功，右侧会显示芯片的UID和Flash大小等信息。
  5. 尝试下载一个简单的LED闪烁程序（hex或bin文件）到0x08000000地址。
  6. 下载完成后，将BOOT0跳线帽改回低电平，按复位键，观察程序是否正常运行。

这个实验能让你最直观地体验USB DFU升级的完整流程。

本章小结

  • USB DFU提供了一种通过USB接口进行固件升级的标准化方法，适合需要高速、免拆机升级的场景。
  • STM32芯片内置了DFU Bootloader，通过配置BOOT引脚或选项字节进入该模式，可直接使用官方工具升级，无需自研Bootloader。
  • DFU设备通过包含DFU功能描述符的USB描述符来告知主机其升级能力。
  • STM32CubeProgrammer是进行USB DFU升级的官方主力工具，操作流程包括连接、选择文件、设置地址和下载。
  • 当需要定制化功能时，可以基于STM32CubeMX和HAL库开发自定义的USB DFU Bootloader，重点实现擦写Flash的回调函数和应用程序跳转逻辑。
