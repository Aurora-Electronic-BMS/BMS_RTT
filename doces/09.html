核心概念扇区解锁

当你通过串口接收到完整的固件数据包并完成校验后，下一步就是将这些数据写入芯片的Flash存储器。这个过程就像给手机安装一个新应用，你需要先清理出足够的存储空间（擦除），再把安装包（固件）写入指定位置。STM32的Flash编程接口就是完成这项工作的工具。

什么是Flash扇区？

你可以把STM32的内部Flash想象成一本书，这本书被分成了很多页，每一页就是一个“扇区”。在写入新内容前，你必须整页擦除，而不能只擦除其中的几个字。不同型号的STM32，这本书的“页数”和“每页大小”都不同。例如，STM32F103系列通常有128KB的Flash，被分成若干64KB和16KB的扇区；而STM32F407系列可能有1MB的Flash，扇区大小从16KB到128KB不等。

STM32 Flash内存布局

在进行任何Flash操作前，你必须清楚目标芯片的Flash具体是如何划分的。这是所有操作的基础。

STM32F1 (小容量)64KB1KB x 64页 (无标准扇区)按页操作，必须先解锁

实际开发中，大部分团队会为每个项目维护一个“memory_map.h”头文件，里面明确定义了Bootloader区、应用程序区、参数存储区各自占用的扇区编号和起始地址。我在项目中踩过这个坑：曾经误将应用程序写入了Bootloader的扇区，导致芯片“变砖”，只能通过串口ISP模式才能救回。

关键点：如何获取正确的扇区信息？

不要硬编码扇区信息。STM32Cube HAL库提供了宏定义来帮助你。对于STM32F4系列，你可以使用FLASH_SECTOR_0到FLASH_SECTOR_11这些宏。更通用的方法是查阅对应芯片型号的数据手册（Datasheet）或参考手册（Reference Manual）中的“Flash memory organization”章节。在代码中，将起始地址和扇区号的映射关系用常量数组定义，是可靠的做法。

HAL库Flash编程核心API

STM32Cube HAL库将复杂的Flash寄存器操作封装成了几个清晰的函数。整个编程流程可以概括为三个步骤：解锁、擦除、写入。

→

下面我们逐一拆解每个步骤需要用到的关键函数和注意事项。

第一步：解锁与锁定

为了防止程序跑飞意外修改Flash内容，STM32在上电后默认将Flash编程接口锁住。在进行擦写操作前，必须输入一个特定的“密钥”来解锁。

// 解锁Flash控制寄存器
if (HAL_FLASH_Unlock() != HAL_OK) {
    // 解锁失败处理，可能是硬件错误
    Error_Handler();
}

// ... 执行擦除和写入操作 ...

// 操作完成后，重新上锁
if (HAL_FLASH_Lock() != HAL_OK) {
    // 上锁失败处理（较少见）
}

常见误区

  • 忘记解锁直接操作：这是最常见的错误，会导致程序卡死在Flash操作函数里。如果你发现程序执行到HAL_FLASHEx_Erase就停了，第一个要检查的就是解锁是否成功。
  • 解锁后未关闭全局中断：在擦写过程中，如果发生中断，可能会打断关键时序，导致操作失败或数据错误。安全的做法是在擦写期间暂时关闭中断。
  • 跨扇区写入：试图一次性写入跨越两个扇区的数据。你必须确保每次写入的地址范围完全落在同一个已擦除的扇区内。

第二步：扇区擦除

擦除操作是以扇区为最小单位的。你需要填充一个擦除配置结构体，指定要擦除的扇区，然后调用函数。

static void Flash_Erase_Sector(uint32_t sector) {
    FLASH_EraseInitTypeDef EraseInitStruct = {0};
    uint32_t SectorError = 0;

    // 配置擦除参数
    EraseInitStruct.TypeErase = FLASH_TYPEERASE_SECTORS; // 按扇区擦除
    EraseInitStruct.Banks = FLASH_BANK_1; // 对于单BANK芯片
    EraseInitStruct.Sector = sector;      // 要擦除的扇区号
    EraseInitStruct.NbSectors = 1;        // 擦除1个扇区
    EraseInitStruct.VoltageRange = FLASH_VOLTAGE_RANGE_3; // 电压范围，通常为3

    // 执行擦除，并检查错误
    if (HAL_FLASHEx_Erase(&EraseInitStruct, &SectorError) != HAL_OK) {
        // SectorError会返回出错的扇区号
        Error_Handler();
    }
}

编者提示：关于FLASH_VOLTAGE_RANGE参数
这个参数容易被忽略，但它很重要。它需要根据芯片的实际工作电压来设置。对于大部分工作在2.7V-3.6V的STM32（如F1、F4系列），应使用FLASH_VOLTAGE_RANGE_3。如果设置错误，可能导致擦除不彻底或写入不可靠。具体值请查阅HAL库头文件（如`stm32f4xx_hal_flash_ex.h`）中的定义和芯片数据手册。

第三步：数据编程（写入）

擦除后的Flash位全部为1（0xFF）。写入操作就是将相应的位从1变为0。HAL库提供了按8位、16位、32位和64位写入的接口。为了提高效率，我们通常使用64位（双字）写入。

static HAL_StatusTypeDef Flash_Write_DoubleWord(uint32_t address, uint64_t data) {
    // 检查地址是否8字节对齐（64位写入的必要条件）
    if ((address & 0x7) != 0) {
        return HAL_ERROR;
    }
    return HAL_FLASH_Program(FLASH_TYPEPROGRAM_DOUBLEWORD, address, data);
}

// 写入一个32位数组的示例
static HAL_StatusTypeDef Flash_Write_Array(uint32_t dest_addr, uint32_t *src_data, uint32_t len_words) {
    HAL_StatusTypeDef status = HAL_OK;
    uint32_t i;
    uint64_t double_word;

    for (i = 0; i < len_words; i += 2) { // 每次处理2个32位字
        // 组合两个32位字为一个64位双字
        double_word = (uint64_t)src_data[i];
        if (i + 1 < len_words) {
            double_word |= ((uint64_t)src_data[i + 1] << 32);
        } else {
            // 如果数组长度为奇数，最后一个双字的高32位补0
            double_word |= ((uint64_t)0 << 32);
        }
        status = Flash_Write_DoubleWord(dest_addr + (i * 4), double_word);
        if (status != HAL_OK) {
            break;
        }
    }
    return status;
}

这里有个隐藏的坑：Flash写入地址必须对齐。64位写入要求地址是8的倍数，32位写入要求地址是4的倍数。如果你看到“编程对齐错误”或程序在此处进入硬故障，首先检查地址对齐问题。

错误处理至关重要。HAL库提供了HAL_FLASH_GetError()函数来获取详细的错误代码。常见的错误包括：

  • HAL_FLASH_ERROR_PGA：编程对齐错误。
  • HAL_FLASH_ERROR_WRP：写保护错误（试图写入被保护的扇区）。
  • HAL_FLASH_ERROR_OPTV：选项字节相关错误。

在实际开发中，你应该在每次Flash操作后检查返回值，并将错误信息通过日志或LED指示出来，这能极大地方便后续的调试和问题定位。

场景：升级小型应用

  • 应用固件小于一个扇区
  • 流程：解锁 → 擦除目标扇区 → 写入数据 → 锁定
  • 注意：擦除会清除同扇区内其他数据

场景：升级大型应用

  • 应用固件跨多个扇区
  • 流程：循环处理每个扇区（擦除→写入该扇区部分数据）
  • 关键：管理好地址偏移，避免数据覆盖错误

场景：写入配置参数

  • 写入少量非代码数据（如校准值、序列号）
  • 可考虑使用最后一个扇区，避免频繁擦写主程序区
  • 需要实现磨损均衡或ECC校验以提升可靠性

动手试一试

在你的STM32开发板上（建议使用STM32F4 Discovery或Nucleo板），创建一个简单的测试工程。编写一个函数，将内部Flash的最后一个扇区（请根据你的板子型号确定扇区号）擦除，然后写入一组固定的测试数据（例如一个递增的数组）。之后，再编写一个读取函数，将写入的数据读出来并通过串口打印，验证写入是否正确。这个练习能让你直观感受Flash擦写的完整过程。

检验你的理解

  1. 判断题：STM32的Flash在写入新数据前，可以直接覆盖旧数据，不需要先擦除。
  2. 选择题：在使用HAL库进行Flash编程时，第一步必须调用的函数是：
    A. HAL_FLASHEx_Erase()
    B. HAL_FLASH_Unlock()
    C. HAL_FLASH_Program()
    D. HAL_FLASH_Lock()
  3. 判断题：为了提升写入速度和安全，在Flash擦写操作期间，最好保持全局中断开启。

本章小结

  • STM32内部Flash被划分为多个扇区，擦除操作以扇区为单位，写入操作需要地址对齐。
  • 使用HAL库进行Flash编程的标准流程是：解锁（Unlock）→ 擦除（Erase）→ 编程（Program）→ 锁定（Lock）。
  • 必须在擦写期间关闭全局中断，并在每次操作后检查HAL返回值，进行详细的错误处理。
  • 不同系列的STM32芯片（如F1、F4、G0）其Flash扇区大小和组织方式不同，编程前务必查阅对应芯片的参考手册。
  • 一个健壮的Flash驱动模块是Bootloader可靠工作的基石，需要仔细设计其流程和错误恢复机制。
