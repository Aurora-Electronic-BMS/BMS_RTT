核心概念页擦除编程操作

接收并校验完固件数据后，最关键的一步就是将数据写入Flash。这个过程就像给一个已经规划好区域的仓库（Flash）更换货物（新固件）。你不能在货物还没搬完时就开门营业，也不能在搬运过程中损坏原有的货架结构。本章将带你走通从数据缓存到Flash编程完成的完整路径。

生活类比

页擦除：就像你要在一页写满字的纸上重新书写，必须先用橡皮把整页擦干净。STM32的Flash也以“页”为单位，写入前必须整页擦除为全1状态（0xFF）。

编程操作：擦干净的纸页，你可以用笔（编程操作）写入新的0和1。但STM32的Flash只能将1写成0，不能将0改回1，这就是为什么必须先擦除。

10.1 写入流程状态机设计

固件写入不是一蹴而就的，它需要一个清晰的状态机来管理。我在项目中遇到过因为状态混乱，导致Flash被意外擦除的严重bug。一个稳健的写入流程通常包含以下几个状态。

空闲(Idle)
→
准备(Prepare)
→
写入(Write)
↓
完成(Complete)
←
错误(Error)

每个状态都有明确的职责和转换条件。例如，只有在校验通过后，才会从“空闲”进入“准备”状态。“准备”状态负责关键的前置操作，比如解锁Flash、擦除目标区域。

常见误区

  • 忘记解锁Flash：STM32的Flash在复位后默认是锁定的，任何编程或擦除操作前必须调用HAL_FLASH_Unlock()，否则硬件会触发错误。
  • 跨页写入不处理：当一次写入的数据刚好横跨两个Flash页时，如果不做特殊处理，会导致后一页的数据被破坏。
  • 中断干扰：在擦除或编程操作过程中被高优先级中断打断，可能导致操作失败或数据错误。

10.2 关键操作详解与配合

理解了状态，我们来看看每个状态下的具体动作。核心是擦除和编程这两个硬件操作，它们的配合决定了写入的效率和可靠性。

10.2.1 页擦除操作

擦除必须以页为单位。对于STM32F4系列，一页大小通常是16KB或32KB，具体需要查阅对应型号的参考手册。擦除操作耗时较长，以STM32F407为例，擦除一页16KB的Flash典型时间在40ms左右。

实际开发中，大部分团队会选择在“准备”状态一次性擦除整个应用程序区域。这样做的好处是流程简单，缺点是升级过程中断电，整个App区域将是空的，需要依赖备份机制恢复。另一种策略是“写前擦除”，即用到哪页擦哪页，更复杂但能提供更好的掉电容忍度。

关键点：擦除函数的阻塞与非阻塞

HAL库提供了HAL_FLASHEx_Erase()函数。你需要关注它的超时参数。我通常设置为一个足够大的值（如5000ms），并确保在此期间看门狗被喂食或暂停。在关键任务系统中，可以考虑使用非阻塞模式，在中断中检查擦除完成标志。

10.2.2 数据编程操作

擦除完成后，进入“写入”状态，开始逐段编程。STM32支持多种数据宽度编程：字节（8位）、半字（16位）、字（32位）和双字（64位）。为了提高效率，我们总是以支持的最大对齐宽度进行编程。

STM32系列Flash编程宽度与函数选择
MCU系列推荐编程宽度HAL库编程函数备注
STM32F1/F0半字 (16位)HAL_FLASH_Program(FLASH_TYPEPROGRAM_HALFWORD, ...)这是F1系列支持的最大宽度
STM32F4/F7/H7双字 (64位)HAL_FLASH_Program(FLASH_TYPEPROGRAM_DOUBLEWORD, ...)效率最高，但数据必须8字节对齐
STM32G0/L0/L4双字 (64位)HAL_FLASH_Program(FLASH_TYPEPROGRAM_DOUBLEWORD, ...)同样推荐双字编程

编程时，你必须确保目标地址是对齐的。例如，使用双字编程时，地址必须是8的倍数。如果从缓存中取出的数据地址不对齐，需要先进行内存对齐处理。

编者提示：Flash编程操作有一个隐藏的坑：它并不是“写入”，而是“清零”。Flash存储单元的初始状态（擦除后）是全1（0xFF）。编程操作只能将特定的位从1变为0，无法将0变回1。这意味着，如果你对同一个地址重复编程而不擦除，只有那些在新数据中为0、旧数据中为1的位会被改变。如果试图将0变为1，操作会被硬件忽略或导致错误。这就是“必须先擦后写”的根本原因。

10.3 完整的流程实现与保护

将状态和操作串联起来，就得到了完整的写入流程。这个流程必须被妥善地保护起来，防止意外干扰。

开始写入流程
→
1. 禁用全局中断
→
2. 解锁Flash接口
→
3. 擦除目标扇区
4. 循环：编程数据块
→
5. 检查编程错误
→
6. 地址递增
↺
7. 锁定Flash接口
→
8. 使能全局中断
→
写入完成

流程中的第一步和最后一步——开关中断——至关重要。Flash编程期间，如果发生中断，尤其是SysTick滴答定时器中断，可能会导致编程操作超时失败。更糟糕的是，如果中断服务程序也位于正在被编程的Flash区域（虽然Bootloader运行时这种情况少见），会引发硬件错误导致系统复位。

下面是一个针对STM32F4系列，使用双字编程的核心代码片段。它展示了从数据缓存写入Flash的循环过程。

static uint32_t write_firmware_to_flash(uint8_t *p_data, uint32_t flash_addr, uint32_t size) {
    uint32_t i;
    uint64_t data_to_write;
    HAL_StatusTypeDef status;

    // 步骤1 & 2: 关中断，解锁Flash
    __disable_irq();
    if (HAL_FLASH_Unlock() != HAL_OK) {
        __enable_irq();
        return FLASH_WRITE_ERR_UNLOCK;
    }

    // 步骤3: 假设扇区已在此前统一擦除，此处直接编程
    for (i = 0; i < size; i += 8) {
        // 从缓存组装一个64位数据
        memcpy(&data_to_write, &p_data[i], 8);

        // 步骤4: 执行双字编程
        status = HAL_FLASH_Program(FLASH_TYPEPROGRAM_DOUBLEWORD,
                                      flash_addr + i,
                                      data_to_write);
        // 步骤5: 立即检查错误
        if (status != HAL_OK) {
            HAL_FLASH_Lock();
            __enable_irq();
            return FLASH_WRITE_ERR_PROGRAM; // 返回具体的错误码
        }
    }

    // 步骤7 & 8: 锁定Flash，开中断
    HAL_FLASH_Lock();
    __enable_irq();
    return FLASH_WRITE_OK;
}

代码中，每次编程后都立即检查状态。一旦发现错误，就立刻停止流程、锁定Flash、恢复中断并返回错误码。这种“快速失败”的策略可以防止在错误状态下继续破坏Flash内容。

场景：小数据量升级

  • 特点：仅更新部分功能，固件体积小。
  • 策略：可采用“写前擦除”策略，仅擦除需要写入的页，升级速度快，掉电风险影响范围小。

场景：全量固件升级

  • 特点：整个应用程序区域被更新。
  • 策略：在开始写入前，一次性擦除整个App区域。流程简单，但擦除期间断电会导致App区域全空。

场景：高可靠性系统

  • 特点：不允许升级失败变砖。
  • 策略：必须结合双备份机制。在新副本写入完成并校验通过前，旧副本始终保持完整可运行。

选择哪种场景策略，取决于你的产品对升级时间、可靠性和存储空间的要求。对于大多数消费类产品，一次性擦除全量升级是平衡了复杂度和可靠性的选择。

动手试一试

在STM32CubeIDE中，基于一个STM32F4 Discovery开发板（或其他F4系列板卡）的Bootloader工程，实现以下功能：

  1. 在内存中定义一个512字节的缓存数组，并填充模拟的固件数据（例如，简单的递增数字模式）。
  2. 编写一个函数，将Flash的第二个扇区（地址0x08004000，假设为App起始地址）擦除。注意先解锁Flash。
  3. 修改上面的write_firmware_to_flash示例函数，将其集成到你的工程中，把缓存数组的数据写入到擦除后的扇区。
  4. 通过调试器或串口打印，验证写入操作是否成功（可以读取写入后的Flash内容与缓存对比）。

这个练习能让你亲身体验从擦除到编程的完整链条，注意观察操作过程中的耗时。

本章小结

  • 流程化设计：固件写入Flash需要一个明确的状态机（如空闲、准备、写入、完成/错误）来管理，确保操作有序。
  • 先擦后写：Flash编程的本质是将位从1变为0，因此写入前必须对目标页进行擦除（恢复为全1状态）。
  • 操作保护：擦除和编程操作期间，应禁用全局中断并解锁/锁定Flash接口，以防止操作被干扰或产生硬件错误。
  • 对齐与效率：根据MCU型号选择最大允许的编程数据宽度（如双字），并确保地址对齐，以提高写入效率。
  • 错误即时处理：每次编程操作后应立即检查返回值，一旦失败立即中止流程并恢复系统状态，避免错误扩散。
