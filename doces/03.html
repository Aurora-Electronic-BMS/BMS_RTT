核心概念启动模式中断向量表

按下开发板的复位键，或者接通电源，你的STM32程序就开始运行了。这个过程看似瞬间完成，但芯片内部其实执行了一套固定的“开机自检”流程。理解这套流程，是设计Bootloader和实现IAP升级的基石。

启动流程类比

你可以把STM32的启动想象成电脑开机：按下电源键（上电复位）后，主板BIOS（芯片内置的固化启动代码）会先运行，它检查硬件并决定从哪个硬盘启动（启动模式选择），然后找到硬盘的第一个扇区（中断向量表），加载操作系统（你的应用程序）。STM32的启动过程与此高度相似。

启动流程的三步曲

STM32从上电到执行你的main()函数，硬件会自动完成三个关键步骤。这个过程不依赖于你写的任何代码，是芯片设计时就固化好的。

上电/复位
→
初始化内核
→
加载PC和SP
↓
执行SystemInit
→
跳转到main()

第一步，芯片内核（Cortex-M系列）从固定的内存地址读取两个初始值：栈顶指针(SP)和程序计数器(PC)。PC指向的位置，就是程序开始执行的第一条指令。

关键点：启动模式决定起始地址

PC最初从哪里读取，由芯片的“启动模式”引脚（BOOT0，部分型号还有BOOT1）在上电复位时的电平决定。这就像电脑的启动菜单，让你选择从C盘还是U盘启动。

STM32的三种启动模式

对于大多数STM32型号（如F1/F4系列），通过BOOT0和BOOT1引脚可以配置三种启动源。这是硬件行为，必须在芯片上电或复位前就设置好引脚电平。

BOOT1BOOT0启动模式起始地址典型应用场景
任意0主闪存启动0x0800 0000运行用户应用程序的常态
01系统存储器启动0x1FFF 0000 (F1) / 0x1FFF 0000 (F4)使用内置的USB DFU或UART串口ISP进行固件升级
11内置SRAM启动0x2000 0000用于调试或运行临时性代码

实际开发中，大部分团队会将BOOT0引脚通过电阻下拉到GND（即模式0），让芯片默认从主闪存启动。当需要利用芯片自带的ISP功能进行“救砖”或初次烧录时，才会在复位前将BOOT0拉高。

常见误区

  • 混淆启动地址与链接地址：启动模式决定的0x08000000是芯片硬件映射的起始地址。你的程序通过链接脚本指定实际存放在Flash的物理地址（通常也是0x08000000），两者必须匹配。
  • 忽略复位后的引脚状态：启动模式只在复位信号的上升沿被采样。如果在程序运行中改变BOOT引脚电平，然后软件复位，新的启动模式才会生效。
  • 误以为SRAM启动能永久保存程序：SRAM掉电数据丢失，从SRAM启动通常只用于临时调试，程序需要通过其他方式（如Bootloader）加载到SRAM中。

中断向量表：程序的“指挥中心”

芯片找到启动地址后，首先看到的就是“中断向量表”。这是一个结构固定的数组，存放在存储器的起始位置。

中断向量表类比

它就像一栋大楼的紧急出口指示图，贴在入口最显眼的位置。图上标明了火灾（复位）、医疗（外部中断）、电梯故障（系统异常）等不同紧急情况发生时，应该前往哪个房间（中断服务函数）处理。芯片一“进门”就先看这张图。

对于Cortex-M内核，向量表的前两个条目必须是初始栈顶指针(MSP)和复位向量（Reset_Handler函数的地址）。之后依次是各种异常和中断的处理函数地址。

// 这是一个简化示意，展示向量表在代码中的结构
typedef void (*isr_func)(void);

__attribute__((section(".isr_vector")))
const isr_func isr_vectors[] = {
    (isr_func)&amp;_estack,        // 初始栈顶地址
    Reset_Handler,             // 复位处理函数
    NMI_Handler,               // 不可屏蔽中断
    HardFault_Handler,         // 硬件错误
    // ... 更多中断向量
};

芯片硬件会从向量表开头取出栈指针初始化MSP，然后取出第二个条目（复位向量）的值，跳转到Reset_Handler函数开始执行。这个函数通常由启动文件（如startup_stm32fxxx.s）提供，用汇编语言编写。

编者提示： 在IAP项目中，Bootloader和应用程序是两个独立的工程，它们各有自己的中断向量表。当从Bootloader跳转到App时，必须将内核的中断向量表指针（VTOR寄存器）重新设置为App向量表的地址，否则中断将无法正确触发App中的处理函数。这是跳转过程中一个非常关键的步骤，也是常见的出错点。

从复位到main()的软件旅程

Reset_Handler是芯片执行的第一段开发者可控的代码。它主要完成以下几项工作：

复制数据段 (.data)
→
清零BSS段 (.bss)
→
调用SystemInit()
→
跳转到main()
  • 初始化.data段：将存储在Flash中的初始值（如已初始化的全局变量`int a = 5;`）复制到SRAM中的对应位置。
  • 清零.bss段：将未初始化的全局变量（如`int b;`）所在的内存区域清零。
  • 调用SystemInit()：这是HAL库提供的函数，负责配置系统时钟（HSI、HSE、PLL）、初始化FPU（如果支持）等关键系统设置。我在项目中踩过这个坑：如果忘记调用或错误配置SystemInit，可能导致系统时钟跑在默认的内部低速时钟（HSI）上，程序虽然能运行，但所有时序（如UART波特率、延时）都会出错。
  • 跳转到main()：完成所有初始化后，最终调用C语言的main()函数，你的应用程序正式接管CPU。

启动文件深度解析

启动文件（.s文件）是理解启动流程的钥匙。以STM32F103的启动文件`startup_stm32f103xe.s`为例，我们关注几个关键部分：

向量表定义

  • 使用`.section .isr_vector`定义段
  • `.word`声明向量表条目
  • 第一个是`_estack`（栈顶），第二个是`Reset_Handler`

复位处理函数

  • `Reset_Handler` PROC/ENDP
  • 调用`SystemInit`初始化系统
  • 调用`__main`（编译器提供）

默认中断服务

  • 为所有中断提供弱定义的默认处理函数
  • 如`Default_Handler: B .`（无限循环）
  • 用户可在C代码中重写

一个隐藏的坑：分散加载

当你的程序非常大，或者像IAP项目那样需要将代码定位到非默认地址时，就需要修改链接脚本（.ld文件）来定义内存区域和段的分布。如果链接脚本中定义的`LOADADDR(.data)`（Flash中的地址）和`ADDR(.data)`（RAM中的地址）不正确，会导致数据初始化失败，变量值异常。排查这类问题，可以检查map文件确认各个段的地址映射。

启动流程对IAP设计的启示

理解了标准启动流程，我们就能设计出IAP方案：

  1. Bootloader本身就是一个标准程序，它被烧录在Flash起始地址（如0x08000000），拥有自己的向量表，上电后首先运行。
  2. 应用程序被烧录到后续地址（如0x08010000）。它的链接脚本需要修改，将其向量表起始地址设置为0x08010000。
  3. 跳转的本质：Bootloader在完成升级后，需要手动将PC（程序计数器）和SP（栈指针）指向应用程序的入口。这通常通过一个函数指针实现，并需要先设置好应用程序的VTOR。

如果你在调试Bootloader跳转时，发现程序“飞了”（进入HardFault），第一步就应该检查应用程序的向量表地址是否正确，以及跳转前是否重新配置了VTOR。

动手试一试

在你的STM32工程中（以STM32F103C8T6为例），找到启动文件（如startup_stm32f103xb.s）。打开它，尝试完成以下观察：

  1. 找到`.section .isr_vector`部分，查看向量表的前几个条目，确认第一个是`_estack`，第二个是`Reset_Handler`。
  2. 找到`Reset_Handler`函数，查看它内部是否调用了`SystemInit`和`__main`。
  3. 编译工程，生成.map文件（在IDE的编译输出文件夹中）。打开.map文件，搜索“isr_vector”，查看它的加载地址（Load Address）和运行地址（Execution Address），理解向量表被存放在哪里以及从哪里被读取。

这个练习能帮助你直观地将理论知识与实际工程对应起来。

检验你的理解

  1. 判断题：STM32的启动模式（如从主闪存或系统存储器启动）是在芯片上电复位时，由BOOT0/BOOT1引脚的电平状态决定的。
  2. 选择题：Cortex-M芯片上电后，硬件自动从向量表读取的第一个和第二个条目分别是？
    A. PC指针和SP指针
    B. SP指针和复位向量
    C. 复位向量和NMI向量
    D. 主堆栈指针和进程堆栈指针
  3. 判断题：启动文件中的`__main`函数就是用户编写的C语言`main()`函数。

本章小结

  • STM32启动是一个硬件主导、软件配合的固定流程，始于复位，终于main()函数。
  • BOOT0/BOOT1引脚电平决定三种启动模式，最常用的是从主闪存（0x08000000）启动。
  • 中断向量表是存储在存储器起始处的函数指针数组，其前两项（初始SP和复位向量）由硬件自动加载，是程序执行的起点。
  • Reset_Handler函数负责初始化.data、.bss段，调用SystemInit配置系统时钟，最终引导至main()函数。
  • 理解标准启动流程是设计IAP方案（修改应用程序链接地址、实现Bootloader跳转）的前提。
