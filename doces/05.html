核心概念独立工程主循环模式

理解了Bootloader的概念和STM32的启动流程后，我们现在要动手搭建一个最简单的Bootloader。这个Bootloader不负责接收固件，它的唯一任务就是：决定是留在原地，还是跳转到另一个程序去执行。你可以把它想象成一个十字路口的交通指挥员，他的工作就是看信号灯，决定车辆是继续在路口待命，还是放行到另一条路（应用程序）上去。

什么是Bootloader最小功能？

最小功能Bootloader是指一个具备最基础决策和跳转能力的程序。它通常运行在芯片启动后，检查某个条件（比如一个按键是否被按下），根据条件决定是执行固件升级流程，还是直接启动已存在的应用程序。本章我们先实现后者——无条件跳转到应用程序。

5.1 创建一个独立的Bootloader工程

这是第一个关键点：Bootloader必须是一个完全独立于应用程序的工程。我在项目中踩过这个坑，曾经试图在一个工程里编译出两个程序，结果链接地址混乱，导致程序根本无法运行。

使用STM32CubeIDE或Keil MDK，你需要像创建普通项目一样，新建一个工程。关键区别在于内存配置。假设我们使用STM32F103C8T6（64KB Flash），一个典型的分区方案如下：

Bootloader0x0800 00008KB存放Bootloader程序
应用程序0x0800 200056KB存放用户应用程序
SRAM0x2000 000020KB程序运行共用

在IDE中配置链接脚本（Linker Script），将Bootloader工程的ROM起始地址设置为0x08000000，大小设置为0x2000（8KB）。这样编译器生成的代码就会乖乖地放在前8KB的Flash里。

常见误区

  • 共用工程：试图在一个工程里通过宏定义区分Bootloader和App代码。这会导致内存布局冲突，是绝对错误的做法。
  • 地址配置错误：忘记修改链接脚本，导致Bootloader程序大小超过了预留区域，覆盖了应用程序的存储空间。
  • 中断向量表忽略：Bootloader运行时使用自己的中断向量表，跳转到App前必须进行重映射，否则App的中断将无法响应。

5.2 Bootloader的主循环模式

Bootloader启动后，它的主循环通常有两种设计模式：单次执行模式和常驻监听模式。对于这个最小功能的版本，我们采用最简单的单次执行模式。

单次执行模式

  • Bootloader启动后，只执行一次决策逻辑。
  • 决策完成后，要么跳转到App，要么自己进入死循环（等待升级）。
  • 优点：逻辑简单，占用资源少。
  • 适用：功能简单的IAP，或通过硬件引脚（如按键）触发升级的场景。

常驻监听模式

  • Bootloader启动后，持续运行，监听通信接口（如串口）。
  • 收到特定命令后，才执行升级或跳转。
  • 优点：可随时触发升级，无需重启。
  • 适用：需要随时通过网络或串口发起升级的复杂系统。

目前，我们让“检查跳转条件”这个步骤永远返回“条件不满足”，从而实现直接跳转。这相当于移除了路口的红绿灯，指挥员看到任何车都直接放行到应用程序那条路。

编者提示：关于“条件检查”的实战经验
在实际开发中，即使你打算永远直接跳转，也强烈建议保留“条件检查”的框架代码（比如检查某个GPIO引脚的电平）。这样，当你后续需要添加真正的升级触发逻辑（如通过按键进入升级模式）时，只需要在该函数内部添加判断即可，无需大幅修改主流程结构。这是一种提高代码可维护性的好习惯。

5.3 实现应用程序跳转

这是本章最核心的技术部分。跳转的本质是修改程序计数器（PC指针）到应用程序的起始地址，并重置堆栈指针（SP）。

跳转前的“大扫除”

在跳转前，Bootloader必须清理好“现场”，确保应用程序在一个干净的环境中启动。主要做两件事：1. 关闭所有已开启的中断；2. 复位所有外设。如果不做这些，应用程序可能会受到Bootloader中配置的外设或未处理完的中断影响，导致行为异常。

以下是实现跳转的关键代码。我们假设应用程序存放在地址 0x08002000。

// 函数：跳转到指定的应用程序地址
void JumpToApplication(uint32_t appAddress) {
    typedef void (*pFunction)(void); // 定义函数指针类型
    pFunction Jump_To_App;

    // 1. 关闭全局中断，防止在跳转过程中被中断打扰
    __disable_irq();

    // 2. 复位所有外设到默认状态（可选但推荐）
    // 例如，如果Bootloader使用了串口，跳转前最好将其DeInit
    // HAL_UART_DeInit(&huart1);

    // 3. 设置堆栈指针(SP)：应用程序的栈顶存放在其起始地址的第一个字
    uint32_t jump_sp = *((__IO uint32_t*)appAddress);
    __set_MSP(jump_sp); // Cortex-M内核函数，设置主堆栈指针

    // 4. 设置程序计数器(PC)：应用程序的复位向量存放在起始地址的第二个字
    uint32_t jump_pc = *((__IO uint32_t*)(appAddress + 4));
    Jump_To_App = (pFunction) jump_pc;

    // 5. 重设向量表偏移量（至关重要！）
    SCB->VTOR = appAddress & 0x1FFFFF80; // 对齐到0x80边界

    // 6. 执行跳转
    Jump_To_App();
}

代码中第5步“重设向量表偏移量”是新手最容易遗漏的一步。Bootloader运行时，CPU的中断向量表指向的是0x08000000（Bootloader自己的向量表）。跳转后，我们必须告诉CPU：“现在中断向量表在应用程序的起始地址了”，否则应用程序的中断服务函数将无法被正确调用。

5.4 主函数与完整性检查

现在，我们将跳转函数整合到Bootloader的主函数中。在跳转之前，一个好的实践是检查目标应用程序是否“看起来像”一个有效的程序。

int main(void) {
    // HAL初始化（时钟、滴答定时器等）
    HAL_Init();
    SystemClock_Config();

    // 简单的GPIO初始化（如果用于条件判断）
    // MX_GPIO_Init();

    // 定义应用程序起始地址
    #define APP_ADDRESS (uint32_t)0x08002000

    // 简易应用程序存在性检查（可选但推荐）
    if (IsValidApplication(APP_ADDRESS)) {
        // 无条件跳转到应用程序
        JumpToApplication(APP_ADDRESS);
    }

    // 如果跳转失败或应用程序无效，则停留在此（后续可改为升级模式）
    while (1) {
        // 可以点亮一个LED表示Bootloader模式
    }
}

// 简单的有效性检查：判断栈顶指针是否在RAM范围内
static int IsValidApplication(uint32_t addr) {
    uint32_t stack_top = *((__IO uint32_t*)addr);
    // 检查栈顶地址是否在SRAM的合理范围内（对于STM32F103，SRAM为0x20000000开始）
    if ((stack_top >= 0x20000000) && (stack_top &lt; (0x20000000 + 20*1024))) {
        return 1; // 有效
    }
    return 0; // 无效
}

IsValidApplication函数是一个最简单的示例。它检查应用程序存储区的第一个字（栈顶值）是否是一个合理的SRAM地址。如果Flash是空的（全0xFF），这个检查会失败，Bootloader就不会跳转，从而可以停留在升级模式。实际开发中，你可以根据需要增加更复杂的校验，比如检查复位向量地址是否在Flash范围内，或者计算整个应用程序的CRC。

  2. 修改工程的链接脚本（通常在“Project Properties > C/C++ Build > Settings > Tool Settings > MCU GCC Linker > General”中修改链接脚本文件），将ROM起始地址改为0x08000000，大小改为0x2000（8KB）。

本章小结

  • 独立工程是基础：Bootloader必须是一个独立的工程，拥有自己独立的内存分区（如0x08000000开始的8KB）和链接脚本配置。
  • 理解主循环模式：单次执行模式简单直接，适合最小功能实现；常驻监听模式更灵活，为后续升级功能预留了框架。
  • 掌握跳转核心步骤：跳转的关键是设置新的SP和PC，并务必重设SCB->VTOR寄存器，否则应用程序的中断将无法工作。
  • 养成检查习惯：在跳转前对目标应用程序地址进行简单的有效性检查（如栈顶指针验证），可以避免跳转到空白或损坏的Flash区域，提高系统鲁棒性。
  • 框架优于细节：即使当前不需要，也在主流程中预留“条件检查”和“应用程序验证”的接口，这会让后续的功能扩展变得非常容易。
