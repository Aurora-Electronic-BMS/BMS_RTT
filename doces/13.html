核心概念升级状态机交互协议

当你已经实现了固件接收、Flash写入和应用程序跳转这些独立功能后，最大的挑战是如何将它们串联成一个稳定可靠的完整流程。一个设计不良的升级流程，就像没有红绿灯和交通规则的十字路口，即使每辆车性能再好，也极易发生碰撞和混乱。

升级状态机：就像电梯的运行逻辑（待机、开门、上下行、关门），它定义了升级过程中Bootloader所处的不同阶段以及阶段间切换的条件。这是整个IAP流程的“交通规则”。

13.1 完整的IAP升级状态机

一个健壮的IAP流程必须是一个确定的状态机。它从等待指令开始，经过一系列不可逆或可回退的状态，最终要么成功跳转到新固件，要么安全地回到起点。我在项目中见过因为状态机混乱，导致Bootloader在升级中途“卡死”，只能通过硬件复位才能恢复的案例。

BOOT_IDLE
等待命令
→
BOOT_RX_HEADER
接收头信息
→
BOOT_RX_DATA
接收固件数据
↓
BOOT_VERIFY
数据校验
↗
BOOT_FLASH
写入Flash
→
BOOT_JUMP
跳转执行
↘
BOOT_ERROR
错误处理
每个状态都有明确的进入条件、执行动作和退出条件。例如，BOOT_RX_DATA状态必须持续接收数据包，直到累计长度达到头信息中声明的固件总大小，才能进入BOOT_VERIFY状态。

关键点：状态机的设计必须考虑所有异常路径。通信超时、数据校验失败、Flash写入错误等，都必须有明确的路径导向BOOT_ERROR状态，并进行清理（如关闭通信、清除接收缓存）后，安全地回到BOOT_IDLE。

13.2 上位机与Bootloader的交互协议

状态机运行需要外部指令驱动，这依赖于一套定义清晰的交互协议。你可以把它想象成客户与银行柜员的对话，必须有固定的“话术”（命令格式）和“凭证”（数据包）。

步骤上位机发送Bootloader响应目的与说明
1. 连接与握手CMD_CONNECT (0x01)ACK_OK + Bootloader版本号建立通信链路，确认设备在线且是目标Bootloader。
2. 获取设备信息CMD_GET_INFO (0x02)ACK_OK + 芯片ID、Flash大小、当前App版本确认设备型号和资源，上位机可据此判断固件是否兼容。
3. 擦除Flash区域CMD_ERASE (0x03) + 起始地址+长度ACK_OK 或 ACK_ERR为写入新固件准备干净的存储空间。这是耗时操作，需处理超时。
4. 发送固件数据CMD_DATA (0x04) + 包序号 + 数据块ACK_OK + 包序号核心传输阶段。数据块大小通常为256/512字节，与Flash编程页对齐。
5. 请求校验和CMD_VERIFY (0x05)ACK_OK + 计算出的校验和Bootloader计算接收数据的校验值，供上位机比对，确保传输无误。
6. 执行跳转CMD_JUMP (0x06) + 新App入口地址无响应（已跳转）Bootloader跳转到新固件，通信会话终止。
7. 复位设备CMD_RESET (0x07)无响应（已复位）可选命令，让设备软复位，重新进入Bootloader或新App。

实际开发中，大部分团队会选择在CMD_DATA和CMD_VERIFY之间增加一个CMD_END_DATA (0x08)命令，用于明确告知Bootloader固件数据已全部发送完毕，可以开始执行校验。这比单纯依赖数据长度判断更可靠。

常见误区

  • 忽略ACK/NAK机制：每个命令都应等待Bootloader的确认（ACK）或错误（NAK）响应后再发送下一条。连续“喷射”命令包是导致通信不同步和升级失败的主要原因。
  • 超时处理过于简单：仅用一个固定超时（如1秒）应对所有操作。擦除Flash（可能几十毫秒）和数据接收（可能因链路拥堵延迟）应有不同的超时策略。
  • 跳转前不做最后检查：在发送CMD_JUMP前，上位机应确保所有数据包已发送且校验通过。Bootloader在跳转前也应再次检查目标地址的栈顶指针是否合法。

13.3 代码实现：整合流程的状态机引擎

下面是一个基于状态机的IAP流程核心代码框架。它使用一个主循环不断检查当前状态并执行相应操作，外部中断（如串口接收完成）或内部事件（如定时器超时）驱动状态变迁。

typedef enum {
    IAP_STATE_IDLE = 0,
    IAP_STATE_RX_HEADER,
    IAP_STATE_ERASE,
    IAP_STATE_RX_DATA,
    IAP_STATE_VERIFY,
    IAP_STATE_FLASH,
    IAP_STATE_JUMP,
    IAP_STATE_ERROR
} IAP_State_t;

static IAP_State_t g_iap_state = IAP_STATE_IDLE;
static IAP_Packet_t g_rx_packet;
static uint32_t g_total_size_received = 0;
static uint32_t g_expected_fw_size = 0;

void IAP_Process(void) {
    switch (g_iap_state) {
        case IAP_STATE_IDLE:
            // 等待上位机连接命令，启动一个连接超时定时器
            if (UART_ReceiveCommand(&amp;g_rx_packet) == CMD_CONNECT) {
                Send_AckWithVersion();
                g_iap_state = IAP_STATE_RX_HEADER;
                Reset_TimeoutTimer();
            }
            break;

        case IAP_STATE_RX_HEADER:
            // 接收包含固件大小、版本等信息的头包
            if (UART_ReceiveCommand(&amp;g_rx_packet) == CMD_HEADER) {
                g_expected_fw_size = g_rx_packet.payload.fw_size;
                if (g_expected_fw_size &gt; MAX_FIRMWARE_SIZE) {
                    Send_Error(ERR_SIZE_TOO_BIG);
                    g_iap_state = IAP_STATE_ERROR;
                } else {
                    Send_Ack();
                    g_iap_state = IAP_STATE_ERASE;
                    Reset_TimeoutTimer();
                }
            } else if (Is_Timeout()) {
                g_iap_state = IAP_STATE_ERROR;
            }
            break;

        case IAP_STATE_ERASE:
            // 等待上位机发送擦除命令，执行Flash擦除操作
            if (UART_ReceiveCommand(&amp;g_rx_packet) == CMD_ERASE) {
                if (Erase_Flash(g_rx_packet.payload.addr, g_rx_packet.payload.len)) {
                    Send_Ack();
                    g_iap_state = IAP_STATE_RX_DATA;
                    Reset_TimeoutTimer();
                } else {
                    Send_Error(ERR_ERASE_FAILED);
                    g_iap_state = IAP_STATE_ERROR;
                }
            } else if (Is_Timeout()) {
                g_iap_state = IAP_STATE_ERROR;
            }
            break;

        case IAP_STATE_RX_DATA:
            // 循环接收数据包，并缓存到外部SRAM或内部缓冲区
            if (UART_ReceiveDataPacket(&amp;g_rx_packet)) {
                if (Cache_WriteData(g_rx_packet.payload.data, g_rx_packet.seq_num)) {
                    g_total_size_received += g_rx_packet.payload.length;
                    Send_AckWithSeq(g_rx_packet.seq_num);
                    Reset_TimeoutTimer();
                }
                // 判断是否接收完毕
                if (g_total_size_received &gt;= g_expected_fw_size) {
                    g_iap_state = IAP_STATE_VERIFY;
                }
            } else if (Is_Timeout()) {
                g_iap_state = IAP_STATE_ERROR;
            }
            break;

        case IAP_STATE_VERIFY:
            // 计算缓存中数据的校验和（如CRC32）
            uint32_t calc_crc = Calculate_CRC32(Get_CacheBaseAddr(), g_expected_fw_size);
            Send_AckWithCRC(calc_crc);
            // 等待上位机发送校验确认或跳转命令
            break;

        case IAP_STATE_FLASH:
            // 从缓存中将数据写入目标Flash区域
            if (Program_FlashFromCache(APP_FLASH_ADDR, g_expected_fw_size)) {
                g_iap_state = IAP_STATE_JUMP;
            } else {
                Send_Error(ERR_FLASH_WRITE);
                g_iap_state = IAP_STATE_ERROR;
            }
            break;

        case IAP_STATE_JUMP:
            // 执行最后的检查并跳转
            if (Check_Application(APP_FLASH_ADDR)) {
                JumpTo_Application(APP_FLASH_ADDR);
                // 跳转后不会返回
            } else {
                g_iap_state = IAP_STATE_ERROR;
            }
            break;

        case IAP_STATE_ERROR:
            // 清理资源：关闭通信、清空缓存、点亮错误指示灯
            Cleanup_Resources();
            Error_LED_Blink();
            // 等待一段时间后自动复位或回到IDLE
            SysTick_Delay(5000);
            NVIC_SystemReset();
            break;
    }
}

编者提示：IAP_Process()函数应在主循环或一个低优先级任务中周期调用。避免在中断服务函数中执行复杂的状态判断和Flash操作。一个实用的技巧是，在IAP_STATE_RX_DATA状态，每成功接收一个数据包，就复位一个独立的“包间超时”定时器（比如100ms），而不是使用一个贯穿整个升级过程的长超时。这能更灵敏地发现通信中断。

13.4 流程的健壮性设计

仅仅实现“晴天”流程是不够的，必须为“雨天”做好准备。健壮性设计体现在对各类异常情况的预防和处理上。

通信中断与恢复

  • 包序号与ACK：每个数据包带有序号，Bootloader必须按序确认。上位机收不到ACK应重发当前包，Bootloader收到重复序号应丢弃包但回复ACK。
  • 断点续传：在CMD_HEADER或CMD_DATA中携带已接收长度信息，允许上位机查询进度并从断点开始发送，而不是从头开始。

电源与系统干扰

  • 关键操作原子性：Flash擦写操作期间若断电，可能导致该扇区数据损坏。设计上应确保一个完整的数据块写入操作（如256字节）是原子的，要么全成功，要么全失败。
  • 看门狗集成：在状态机的每个循环中喂狗，但在执行Flash擦写等阻塞操作时，需要临时暂停看门狗或使用更长的超时时间。

内存与存储安全

  • 边界检查：对接收到的固件大小、目标写入地址进行严格检查，防止数据溢出到Bootloader区域或其他受保护区域。
  • 缓存管理：如果使用外部SRAM做缓存，需在启动时进行内存测试。在写入Flash前，可对缓存中的关键区（如中断向量表）进行预校验。
